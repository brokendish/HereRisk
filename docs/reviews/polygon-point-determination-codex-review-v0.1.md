## 2. BLOCKER（1件）

### B1: 逆向きに重複する辺の相殺により、H2成立でも解釈が分かれる

1本の外周リング、穴なし。以下は北緯35度・東経139度を原点とする研究と同じ局所メートル座標。`point_study._poly`で経緯度に変換する。

```python
ring = [(0,0), (1000,0), (1000,1000), (0,1000), (0,0),
        (0,1000), (1000,1000), (1000,0), (0,0),
        (-1000,0), (0,-1000), (0,0)]
point = (500,500)
```

正方形を反時計回り・時計回りに1回ずつ通り、原点で接する別の三角形を反時計回りに回る。正方形の回転数は相殺される。三角形は地点を囲まないが、リング全体の符号付き面積を正（500,000 m²）にする。面積0の環ではない。再現に余分な穴・Feature・ランダムデータは必要ない（頂点数の数学的最小性は主張しない）。

| 根拠/方式 | 結果 |
|---|---|
| リングごとのraw回転数 | `[0]` |
| 面積の符号 / 正規化回転数 | `+1` / `0` |
| 偶奇 / H / H2 | 外側 / true / true |
| 原典の最寄り境界 | 約499.973m |
| 研究実装の問題点までの距離 | 約707.09m（重複辺の端点の記録に対する距離） |
| even_odd / nonzero | **outside** |
| make_valid(linework) | **inside** |
| make_valid(structure) / buffer(0) | **outside** |
| 現行study_class | `interpretation_dependent` |
| 現行局所法100 / 500 / 1,000m | 境界なし / 最寄り不一致 / 最寄り不一致、いずれも不採用 |

独立した根拠として、整数座標の符号付き面積、角度積分（`atan2`の和、半直線交差数とは別方式）、正方形と三角形への所属、GEOSへの直接呼出しを併用した。研究ラッパーの分類による見かけの不一致ではない。逆順でも再現し、全座標・地点を4倍にして境界から約2km離しても再現する。

この例では、原典の辺の**通過回数**を保存する偶奇と、重複した線を含むGEOS linework修復の結果が一致しない。従って「lineworkは偶奇系に近い」は検証の整理として使えても、全入力で同一とは扱えない。どちらが原典作成者の意図かは判断していない。

**実装前に必要な対応（製品変更は本監査では行わない）:**

- H2が保証するのは定義された偶奇と正規化nonzeroの一致まで、と採用仕様に明記する。研究第9・10章のH2からB分類へ進める記述は、この反例を含めて適用範囲を限定する。
- 少なくとも本反例のような重複辺・往復による相殺は、H2成立でも判定保留にする。地点から遠いという理由では解除しない。既存の構成全体の`defects.kind = overlap`は保留の根拠に利用できる。ただし「overlapを除けば常に十分」とは本監査で証明・検証していない。
- 適用範囲が定まるまではH2を事実として返し、無効な構成をH2だけで確定した区域外・該当なしへ落とさない。既存v1の保留を維持する段階的実装は可能。

## 3. NOTE（重要なもののみ）

1. **境界の閾値判定より前の丸め:** `ring_facts`は距離を小数4桁に丸め、`interpretations`と`study_class`がその値を`< 0.001`で比較する。正方形の辺から0.00096m内側では、距離が0.001となり`determinate`、0.00094mでは`on_boundary`になることを確認した。内外の逆転ではなく約0.05mm幅の保留帯の差であるためNOTE。次工程では未丸め距離で閾値を判定し、表示のみ丸める。閾値ちょうどを含むかも固定する。1mmの最適性・GPS精度は今回決定しない。
2. **低メモリは索引だけでは自動的に保証されない:** 現行`_segments_in`は該当chunkを全て集めて配列結合する。最悪時は全線分を読み得る。共通Engineではchunkを逐次集計することで回転数計算の作業メモリをリング数＋1chunk程度にできる。候補上限・時間上限と保留を維持する。実索引でのH2計測は今回未実施。

## 4. H2条件の監査結果

文書第3章と`assess`は一致している。`per_ring_unit`単体はリング条件だけだが、`assess`の公開する`h2_per_ring_unit`はHとの論理積であり、欠落ではない。

- 保存方向の回転数をr、各リングの面積符号をaとし、aが非零ならa·rが0または1。面積0ならr=0を要求する。
- 外周を加え、穴を引く合計wが0または1、偶奇がwと一致することも要求する。
- これらは選んだ偶奇とnonzeroの一致を保証する。穴が外周外で単独に地点を囲む、複数の穴が地点で重なる、2回巻きなどは合計条件またはリング条件で排除できる。
- リング反転はaとrを共に反転させるため、正規化値を変えない。追加反例でも確認した。
- しかしr=0には「周囲を回らない」以外に「逆向きの通過の相殺」が含まれる。H2はその違いを識別しない。原典作成者の意図、GEOS全方式の一致は保証しない。
- `study_class`はH2採用器ではなく、実際の5方式を比較する研究分類である。今回の反例を正しく不一致に分類する。H2不成立でも5方式が一致する場合はあり、不成立を必ず不一致と断定する必要はない。製品採用では保留してよい。

## 6. 遠方の不整合

既存C10・C12・C16等の不一致とH2不成立、局所法の不採用は研究テストで再確認した。全体回転数は探索半径に切り詰めず、全リングから半直線に交差する辺を数えている。距離だけで内外を決めていない点は妥当。

B1はさらに、遠方の重複構造がH2でも見抜けない場合を示す。4倍形状で境界が約2km先でも不一致が残る。距離制限を拡大するだけでなく、構成全体の適用可否と保留を保持する必要がある。

## 7. SQLite診断索引の再利用可能性

**形式変更なしに必要な根拠を取得可能。** `comps.rings`に穴フラグ・面積符号・線分数、`chunks`にリング番号と連続float64頂点がある。64線分のchunkは端点を共有するが、辺を二重計上しない。現行`winding`の`raw`は既にリングごとの値で、返却前に合計へ縮約されるだけである。交差しないリングも0で埋める必要がある。

最短の東西南北の半直線を選ぶ座標変換はいずれも向きを保存する回転であり、rawの符号を壊さない。一時SQLiteに既存スキーマで保存し、chunk分割を跨ぐ相殺・穴と4方向の地点を、角度積分によるリング値、現行`winding`の合計・偶奇と照合して一致した。既存索引を書き換える検証はしていない。

検索はR-treeのbboxによる候補抽出後、float64の端点を使う。取得できるのは半直線に交差する**chunk候補**であり、交差辺そのものだけではない。今回の`EXPLAIN QUERY PLAN`では`chunks_key (comp=?)`検索とR-tree副問合せが選ばれた。従って研究の「計算量は半直線と交わる塊だけに比例」は、SQL検索コストまで含む厳密な上限ではない。構成内chunk走査や、他構成も含むR-tree候補集合が費用に加わり得る。方式が実用上成立しない証拠はなく、現段階で索引形式を変更する理由はない。

境界の保留判定は回転数とは別に近傍bbox内の線分距離を調べればよく、全Polygonを常駐させる必要はない。全体の最短距離を返す場合は拡大検索等の実装・計測が別途必要で、本監査で性能確認済みとはしない。修復Geometryの生成はオンライン要件に含めない。

## 8. 共通Polygon Engineへの引継ぎ条件

1. raw回転数・面積符号・穴の役割・H2・境界近傍・構成の不整合を事実として取得する実装は開始できる。
2. **B1を採用仕様と回帰テストへ反映し、H2単独で解釈一致や確定区域外を返さない。** 無効構成の適用対象を限定し、少なくとも重複辺の相殺例は全体の構造に基づき保留する。H2以外の適用条件の十分性は別途確認する。
3. 境界、Featureレベルの不確定性、根拠不足、読取失敗・上限超過・時間切れは区域外に変換しない。共通契約v0.2の`complete:false / features:null`と正式・参考の分離を維持する。
4. chunk逐次処理と未丸め境界判定を実装し、実索引で限定的に計測する。原典意図の一致は主張しない。

必要なのはH2の採用範囲と保留条件の修正であり、低メモリの共通計算基盤の断念ではない。
