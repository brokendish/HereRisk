# ADR-002（案）: Polygon Engineは幾何の事実だけを返し、意味と採用基準はハザードが持つ

- 状態: **PROPOSED（OWNER未決定）**
- 作成: 2026-11-02（Claude、Phase 4-H 設計レビュー）
- 関連: [設計レビュー](../architecture/polygon-engine-review-v0.1.md)、[契約案](../api/polygon-engine-contract-draft-v0.1.md)、[移行計画](../architecture/polygon-engine-migration-plan-v0.1.md)、[ADR-001](2026-10-25-multiple-official-hazard-results.md)

## 背景

洪水（A31a）で、無効Polygonの扱い（判定保留、診断、参考解析API）を実装した。津波・高潮・土砂災害もPolygonの原典を持ち、同じ処理の多くを必要とする。共通化しないと実装が重複し、共通化しすぎると洪水の基準や意味を他のハザードに強制する。

## 決定（案）

1. 共通のPolygon Engineは、**幾何の事実と処理の状態**（内外・境界上・形状の有効性・局所の読みと根拠・方式・世代・上限超過・失敗）だけを返す。
2. 属性の意味（浸水深・区域区分）、状態の対応（`no_match` など）、採用方針（`candidate` の条件）、利用者への文言、出典・利用条件は、**各ハザードが持つ**。
3. 索引は形式だけを共有し、ファイル・世代・設定はハザード（API）ごと・ソースごとに分ける。
4. 無効形状の修復の関数をEngineに置かない。
5. 独立検証はEngineを使わない。
6. 共通部品は、2つ目の利用者が使う時点で切り出す。既存の洪水は、回帰基準に合格するまで移行しない。
7. （2026-11-03 Phase 4-H.1 で追加）原典の形状状態（データ提供元の作った形の事実）と、HereRiskの探索・解析状態（探索半径・方式の版に依存する結果）を、**別々の情報として返し、排他的に分類しない**。探索の上限（例: 最大半径の中に境界がない `no_local_boundary`）や方式の限界を、原典の不備として説明・集計しない。

## 結果

- 良い点: 新しいハザードが、洪水の意味・基準に縛られずに共通の幾何を使える。洪水の結果は変わらない。
- 悪い点: 移行の途中は、同じ規則の実装が2つ並ぶ（差分テストで一致を保つ）。ハザードごとに採用方針と文言を用意する手間がある。

## 却下した案

- **1つの共通サービス（プロセス）にすべてのハザードのPolygon判定を集約する**: 低メモリ環境で単一障害点になり、データの所有権・世代が連動する。
- **洪水のコードを先に共通部品へ移動する**: 洪水の結果を変える危険を、利用者のいない段階で負う。
- **共通Engineに既定の採用方針を組み込む**: 未検証のハザードへ洪水の基準が流れ込む。
