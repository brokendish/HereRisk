# ADR-002: Polygon Engineは幾何の事実だけを返し、意味と採用基準はハザードが持つ

- 決定日: 2026-11-03
- 決定者: OWNER（Phase 4-I の指示による採用）
- 状態: **ACCEPTED**
- 経緯: 2026-11-02 Phase 4-H で案として作成（旧ファイル名 `2026-11-02-polygon-engine-responsibility-draft.md`）、2026-11-03 Phase 4-H.1 で第7項を追加、同日 Phase 4-I で採用
- 関連: [Polygon Engine 共通契約 v0.2](../api/polygon-engine-contract-v0.2.md)、[設計レビュー](../architecture/polygon-engine-review-v0.1.md)、[移行計画](../architecture/polygon-engine-migration-plan-v0.1.md)、[Polygon判定理由カタログ v0.2](../api/polygon-reason-catalog-v0.2.md)、[ADR-001](2026-10-25-multiple-official-hazard-results.md)
- 注意: このADRは責務の分け方の決定である。共通Engineの実装、新しいハザードの実装、参考解析の正式採用、データの公開を承認するものではない。

## 背景

洪水（A31a）で、無効Polygonの扱い（判定保留、診断、参考解析API）を実装した。津波・高潮・土砂災害もPolygonの原典を持ち、同じ処理の多くを必要とする。共通化しないと実装が重複し、共通化しすぎると洪水の基準や意味を他のハザードに強制する。

## 決定

1. 共通のPolygon Engineは、**幾何の事実と処理の状態**だけを返す。
   - 形状の有効性
   - 内外・境界接触の幾何学的関係
   - 局所探索の結果
   - 探索条件・上限
   - 判定に利用した方式・版
   - データと索引の世代情報
   - 処理状態
2. **各ハザードのProviderが持つ**もの:
   - 原典フォーマットと属性の解釈
   - 浸水深・警戒区域などの意味
   - 診断結果の採用条件
   - 公式APIの状態への対応
   - 出典・利用条件
   - 利用者向けのハザード固有の表現
3. 共通Engineは、防災上の独自スコア・危険度・安全判定・ハザード間の統合を行わない。
4. **既存の洪水の採用条件（`flood-diagnosis-adoption-v1`）を、他のハザードの既定として強制しない。** 採用条件はハザードごとに版を付けて持つ。
5. 原典の形状状態（`geometry_state`）と、HereRiskの探索・解析状態（`analysis_state`）を、**別々の情報として返し、排他的に分類しない**。探索の上限（例: `no_local_boundary`）や解析方式の限界を、原典の不備として説明・集計しない。理由コードには直接の原因の区分 `cause` を付ける（Phase 4-I で実装）。
6. 索引は形式だけを共有し、ファイル・世代・設定はハザード（API）ごと・ソースごとに分ける。正式索引と診断索引は組で切り替える。
7. 無効形状の修復の関数をEngineに置かない。
8. 独立検証はEngineを使わない。
9. 共通Engineの配置は `hererisk.common.polygon` とする。共通部品は、2つ目の利用者（次のハザード）が使う時点で切り出す。既存の洪水は、回帰基準に合格するまで移行しない。

## この決定に含まれないこと（別工程・OWNER判断）

| 事項 | 参照 |

| 次のハザードを津波（A40）とするか | 設計レビュー U-1 |
| 局所輪郭法の正本（メモリ上かSQLite上か） | 設計レビュー U-2（配置だけを決定した） |
| 索引の Data Publish・Dataset Registry での世代管理 | U-3 |
| 複数ハザードのメモリの方式 | U-4 |
| 座標の精度プロファイル（整数・8桁）の採用 | U-5 |
| WGS84 と JGD2011 の扱い | U-6 |
| 共通の既定の採用方針を置くか | U-7 |
| A40・A49の原典の自己接触の扱い | U-8 |

| 正当な接触を問題箇所の判定から外すか | U-12 |

## 結果

- 良い点: 新しいハザードが、洪水の意味・基準に縛られずに共通の幾何を使える。洪水の結果は変わらない。探索の限界をデータ提供元の問題に見せない。
- 悪い点: 移行の途中は、同じ規則の実装が2つ並ぶ（差分テストで一致を保つ）。ハザードごとに採用方針と文言を用意する手間がある。

## 却下した案

- **1つの共通サービス（プロセス）にすべてのハザードのPolygon判定を集約する**: 低メモリ環境で単一障害点になり、データの所有権・世代が連動する。
- **洪水のコードを先に共通部品へ移動する**: 洪水の結果を変える危険を、利用者のいない段階で負う。
- **共通Engineに既定の採用方針を組み込む**: 未検証のハザードへ洪水の基準が流れ込む。
- **探索の上限を原典の不整合の一種として分類する**: 有効なPolygonでも起きる（Phase 4-C の対照60組）ため、事実に反する。
