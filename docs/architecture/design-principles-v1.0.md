## 1. 背景と目的

OnHighGround2で複数の公式防災データを扱う中で、**同じ地点でも、公表主体や想定条件によって結果が異なる**ことが明らかになった［確定］。一つの結果だけを利用者に示すと、他の公式情報の存在や差異が伝わらず、誤解につながる可能性がある［確定］。

HereRiskは、複数の公式情報を独断で統合・順位付けして唯一の正解を決めるのではなく、各情報の出典と前提条件を保持して提示する［確定］。**利用者にデータの正当性を判定させることは目的としない**［確定］。

本書は、この基本理念を、すべてのAPI個別契約より上位の設計原則として定める。

## 2. 最上位原則［確定］

> **公式情報の違いを隠さない。**
>
> **内部は厳密に。外部はシンプルに。不確実性は隠さない。**

## 3. 規範

各原則の原則文は［確定］（OWNER決定）である。「適用」は、現行の契約での対応を示す［提案］。

### 3.1 公式データ忠実提示方式［確定。2026-10-25 OWNER決定］

**現在地に関係する公式防災情報を、原典の内容・出典・条件を保持して、複数あればすべて独立して提供する。**

- HereRiskは、異なる公式データの正誤・信頼性・優劣を判定しない。
- 複数の公式データを比較し、独自の代表値や危険度を算出しない。
- 利用者にデータの正当性判断を要求しない。
- 公式データ間の違いが存在することを、利用者が認識できるようにする。
- 原典にない説明や結論を付与しない。
- 検索対象として採用・公開されたデータは、欠落なく返却する。
- unknown、取得失敗、未収録、評価範囲不明を安全や危険なしに置き換えない。

これはMVPの縮小ではなく、HereRiskの正式仕様である。この方針に反する旧設計（公表主体の自動優先、代表値、ソース間の深さの比較、独自の集約、独自の安全・危険判定）を実装しない。廃止した機能の一覧の正本は [Flood Official Data Presentation Contract 第3章](flood-official-data-presentation-contract-v0.1.md) である。

### DP-01 原典尊重

**原則**［確定］: 公式データの原典、属性、来歴、想定条件を保持する。正規化・地点判定によって生じた結果は原典と区別する。

**適用**［提案］: 原典の完全保持と、原典忠実性の検証・妥当性の評価・派生形状の分離（Flood Normalize契約 第1.4節 P-1〜P-6・第4.5節）。原典属性・来歴の統合成果物への保持（Flood Integration契約 第5章・第6.2節）。原典の浸水深区分をコード・定義の文言・区間・版のまま返す（Flood Official Data Presentation契約 第7.2節）。

### DP-02 複数結果の独立性

**原則**［確定］: 異なる公式データの結果を独立して扱う。明確に定義・承認された処理を除き、複数の結果から独自の唯一の正解を生成しない。

**適用**［提案］: ソースごとの独立した地点検索（Flood Official Data Presentation契約 第7.1節）。形状だけを根拠とした重複排除の禁止（Flood Integration契約 第5章）。「明確に定義・承認された処理」に、公式の結果どうしの比較・順位付け・代表値・集約は**含まれない**（DP-11）。

### DP-03 情報の網羅的提示

**原則**［確定］: 公開対象として採用したデータに複数の結果があれば、原則としてすべて提示・参照可能とする。未登録・未収録の公表データまで網羅しているとは主張しない。

**適用**［提案］: 全ソース・全区域・全unknownの返却と、切捨ての禁止（Flood API MVP契約 第5.4節）。目録の所属の完全性（Flood Official Data Presentation契約 第5章）。候補の列挙範囲と `candidate_completeness = not_guaranteed`（同 第6章）。

### DP-04 非恣意的な表示

**原則**［確定］: 特定の公表主体を信頼性の順位によって自動優先しない。初期表示は全登録ソースのoverviewを基本とする。表示順、フィルター、主表示の選択を、データの正誤判定と混同しない。

**適用**［提案］: APIは常に全ソースの結果を返し、絞り込み・主表示の切替えはUIが属性で行う（Flood Official Data Presentation契約 第9章）。表示順は信頼性の順位ではない（同）。

### DP-05 違いの理解を支援

**原則**［確定］: 出典、提供主体、対象河川、想定シナリオ、作成時期、評価条件など、原典から確認できる情報を関連付ける。異なる結果について、根拠がない原因説明を生成しない。「結果が異なる」という事実と「なぜ異なるか」という解釈を区別する。

**適用**［提案］: Source Catalogの公表元・対象河川・シナリオ・版・出典を、ソースごとの結果と並べて返す（Flood Official Data Presentation契約 第4.3節・第9章）。結果の違いの原因を推測する項目は設けない。

### DP-06 利用者に正当性判定を強制しない

**原則**［確定］: 利用者は河川別、提供主体別、個別データソース別などの視点で情報を確認できる。これらは情報を理解するための操作であり、利用者が一つの公式データを正解と認定する操作ではない。

**適用**［提案］: 視点の切替えは、データに付与された属性によるUIの絞り込みで行い、分類の目的で原典を重複して登録しない（Flood Official Data Presentation契約 第4.1節・第9章）。`source_id` の粒度は未決定（同 PD-U1）。

### DP-07 不確実性の明示

**原則**［確定］: unknown、評価範囲不明、比較不能、未収録、公開対象外、取得失敗を区別する。これらを「浸水なし」「安全」「危険なし」に変換しない。

**適用**［提案］: 派生状態を作らず、事実を表す項目で5つの区別（確認済み区域への該当・検索したが確認済み該当なし・不明または判定不能・データ未収録または対象外・取得失敗または整合性エラー）を表す（Flood Official Data Presentation契約 第8章、Flood API MVP契約 第6章）。HereRiskはソース間の比較を行わないため、「比較不能」は原典どうしの比較の結果としては生じない。プロジェクト定義書 P5「不明を安全と判定しない」・第7章と整合する。

### DP-08 安全上の情報の保持

**原則**［確定］: 利用者が絞り込みや選択を行っても、他のソースに確認済みの深い浸水想定やunknownが存在する事実を隠さない。表示の簡略化によって、安全上の重要情報を欠落させない。

**適用**［提案］: APIは常に全ソースの全区域（原典の浸水深区分つき）と全unknownを返す。UIで絞り込み・主表示の切替えをしても、他のソースの結果とunknownを参照できるようにする（Flood Official Data Presentation契約 第9章）。HereRiskは「深い」を独自に判定しない。各ソースの原典の区分を並べて示すことで、深い想定の存在を隠さない。原則文は洪水を例にしているが、他のハザードにも同じ趣旨で適用する。

### DP-09 責務分離

**原則**［確定］: Source Discovery、Point Assessment、Source Selection、API、UIを分離する。データの登録・評価・選択・表示を、単一の巨大な判定ロジックに統合しない。

**適用**［提案］: Discovery（目録の列挙）、ソースごとの地点検索、API（入出力）、UI（絞り込み・主表示の切替え）を分ける（Flood Official Data Presentation契約 第6章〜第9章）。原則文の「Source Selection」は、現行の契約では利用者がUIで行う絞り込み・切替えに当たり、サーバ側の選択の処理は持たない。プロジェクト定義書 P1・P2と整合する。

### DP-10 検証可能性

**原則**［確定］: 原典・判定結果・公開世代・設定・来歴を追跡可能にする。結果の完全性・整合性を検証できる契約を定義する。

**適用**［提案］: 内容ハッシュと実行証跡、Recordの一方向の確定順序（Flood Normalize契約 第11章、Flood Integration契約 第7章）。公開世代への設定の固定と目録の照合（Flood Official Data Presentation契約 第5章・第10章）。プロジェクト定義書 P4と整合する。

### DP-11 公式結果を比較・順位付け・集約しない［確定。2026-10-25 OWNER決定］

**原則**［確定］:

- 公式の結果の比較・順位付け・代表値の算出を、HereRiskが独自に行わない。
- 複数の区域は、原則として個別に返す。
- 利用者に正誤の判断を求めない。
- 不確実性は保持する。
- 原典の品質検証は引き続き必要である。
- 内部の処理と、利用者に提示する判断を区別する。

**適用**［提案］: 内部の処理（原典の忠実性の検証、幾何の妥当性の評価、空間検索、所属の照合、世代の照合）は厳密に行う。それらは原典を正しく保持・検索するための処理であり、利用者に提示する判断（安全・危険、どのデータが正しいか、どれが代表か）を生成しない。原典に最初から存在する区分（例: 浸水深ランク）を原典のまま返すことと、HereRiskが独自に算出する危険度は別物である。

## 4. 契約上の位置付け［確定］

- 本書は、HereRiskの**共通設計における最上位文書**とする。
- 共通API契約と各ハザードの個別契約は、本書と整合しなければならない。
- **本書だけを根拠に、既存のセキュリティ・利用条件・公開認可・データ検証の禁止事項を緩和してはならない。** 例えば、DP-03（網羅的提示）を理由に、利用条件が未解決のデータ、公開認可のないデータ、検証に合格していないデータを提示しない。
- 矛盾を発見した場合は、既存契約を無断で変更しない。対象の条項・影響・改訂案を記録して、OWNERの判断を求める。

**プロジェクト定義書との関係**［提案］: プロジェクト定義書は、プロジェクトの目的・範囲・開発基本原則（P1〜P11）を定める文書である。本書は、その下で、設計文書の最上位に位置付ける案とする。正式な決定はOWNER判断とする（DP-U1）。

## 7. 本書の確定が意味しないこと
