## 0. 要点

1. **内外の判定は、探索半径ではなく、地点を通る1本の半直線で求めるリングごとの回転数で決まる。** Polygonの大きさ・地点から不整合までの距離は、判定の数学的な成否を決めない。遠方の不整合でも、地点の面の回転数を変えていれば判定に影響する（反例: 合成 C10 は交点から約1.5km、C12・C16 は約0.5〜1.4km離れた地点で解釈が分かれる）。
2. **「全体の回転数が0か1で、偶奇と一致する」（条件H）だけでは足りない。** 外周が地点の周りを2回回り、穴が1回引く面（合計1）で、`make_valid(structure)` だけが外側と読む反例を、ランダム探索で35件見つけた。**リングごとの回転数がすべて0か1**（条件H2）を加えると、約17.8万点の探索・合成形状・東京都の実データのすべてで、5つの解釈が一致した（反例0）。ただしこれは観測であり、GEOSの修復方式についての証明ではない。
3. **東京都・洪水の固定検証セットでは、無効2,113組のすべてでH2が成り立ち**、境界上（1mm以内）の50組を除く2,063組で5つの解釈が一致した。`no_local_boundary` の976組もすべて一致した（外側886・内側90）。現行の参考解析で判定保留の1,640組のうち1,590組は、解釈の上では一致している。
4. **解釈の一致は、原典作成者の意図との一致ではない。** 東京都の不整合は全て頂点の自己接触（touch）で、自己交差・反転した部分は観測されていない。解釈が分かれやすい型が、検証セットに含まれていない。
5. **探索半径を広げても、現行の採用条件では判定できる組が減る。** 条件を満たす組は 100m: 487 → 500m: 128 → 1,000m: 44（最大半径の中に問題箇所がないことを求めるため）。半径の拡大は解決策にならない。
6. 共通Engineには、**リングごとの回転数（H2の根拠）・偶奇・境界までの距離・Feature内の重なり**を事実として返させ、採用はハザードの方針に任せることを推奨する（第10章）。採用の前に、Codexの監査・精度の評価・他地域と他ハザードでの検証・原典との照合（意図）が必要（第11章）。

## 1. 判定問題の定義

地点 p と、原典の構成Polygon（外周1つ＋穴0個以上。各リングは閉じた折れ線）について、p が「内側」「外側」「境界上」のどれかを問う。

| 区別 | 意味 | 本書で確かめられるか |
|---|---|---|
| **A. 数学的な内外関係** | 選んだ幾何の定義（規則）のもとで、p がどこにあるか | できる（規則ごと） |
| **B. 複数の解釈での一致** | 無効なPolygonに、実質的に異なる複数の規則を当てたとき、p の関係が一致するか | できる（選んだ規則の範囲で） |
| **C. 原典作成者の意図との一致** | その関係が、作成者が意図した浸水想定区域と一致するか | **できない**（原典の作成記録・公式の図面との照合がない） |

- 有効なPolygonでは、どの妥当な規則でも同じ答えになる（A＝B）。正式判定（GEOS）はこの場合だけに使っている。
- 無効なPolygonでは、規則ごとに答えが決まる（Aは常に「ある規則のもとで」）。Bは規則の選び方に依存し、Cとは別である。

## 2. 比較した方式

| 方式 | 規則 | 系統 |
|---|---|---|
| `geos_raw` | GEOS の `contains` を無効な入力にそのまま当てる | **解釈として数えない**（無効な入力での結果は定義されない。記録のみ） |
| `even_odd` | 全リングの半直線との交差数の偶奇 | 偶奇系 |
| `nonzero` | 正規化した回転数 ≠ 0（各リングを自分の符号付き面積で向き付け、穴は引く） | 向き系 |
| `make_valid_linework` | GEOS: 線を交点で分割し、面を偶奇で選ぶ | 偶奇系（`even_odd` に近い。独立した証拠として数えない） |
| `make_valid_structure` | GEOS: 外周の面積の合併から穴の合併を引く（リングの役割による） | 役割系 |
| `buffer0` | GEOS: `buffer(0)`（保存された向きと面の向きによる） | 向き系（`nonzero` とは向きの扱いが異なる） |
| 局所輪郭法 | Phase 4-C/4-D の規則（最寄りの輪郭の側＋回転数＋偶奇＋問題箇所の距離）。半径 100・500・1,000m まで段階的に | 判定方式ではなく、局所の根拠の確認 |

- 実質的に異なる規則の系統は3つ（偶奇系・向き系・役割系）。同じ系統の一致を、独立した正解の証拠として数えない。
- `make_valid`・`buffer(0)` は検証用で、正式判定のデータに使っていない。

## 3. 方式の関係（数学的な整理）

p がどのリングの上にもないとき、リング k の回転数 r_k（保存された向きでの、p の周りを回る回数）は、半直線1本との交差の符号付きの数で厳密に決まる。

- 偶奇 = Σ r_k の偶奇（交差数の偶奇は回転数の偶奇に等しい）
- 正規化した回転数 w = Σ s_k · a_k · r_k（a_k: リングの符号付き面積の符号、s_k: 外周 +1・穴 −1）
- したがって `even_odd` と `nonzero` は、**p でのリングごとの回転数だけ**で決まる。不整合がどこにあるかは、それ自体では関係しない。不整合が p の面の回転数を変えていれば影響し、変えていなければ影響しない。
- **H2**（各リングの a_k·r_k が 0 か 1、面積0の環は p の周りを回らない、w ∈ {0,1}、偶奇が w と一致）が成り立つとき、p は「外周の内側に1回だけ、穴の内側に高々1回」という単純な状態にあり、上の2つの規則は一致する。
- GEOS の3方式（linework・structure・buffer(0)）は実装で定義された規則で、上の式で表せない。H2 のもとで一致することは**観測**であり、証明していない。

  - 東京都・洪水（A31a 2025年版、3つのZIP）だけ。全国・他のハザードには一般化しない。

### 6.4 現行の採用条件について見つかったこと

1. **現行の条件はHを確かめているが、H2は確かめていない。** 局所の読み＋正規化した回転数＋偶奇の一致は、Hの反例（外周が2回巻き、穴が1回引く面）を通しうる。東京都のデータでは該当がなかった（全組でH2が成立）が、他のデータへ広げる前に確認が必要。
2. **面積0の環の扱いが、局所と全体で異なる。** 局所の読みは、最寄りの輪郭が面積0の環である場合だけ止まり、全体の読みは、構成のどこかに面積0の環があれば止まる。本来は「その環が地点の周りを回るか」で判断すべき（東京都では20組が該当し、7組は現行の `candidate`。いずれも環は地点の周りを回っていない）。
3. 局所輪郭法の2つの実装（メモリ上・SQLite上）は、半径1,000mまで広げても2,113組すべてで一致した（Phase 4-D の確認を100mから1,000mへ広げた）。

## 8. 判定結果の分類（研究用）

既存の `candidate / undetermined / rejected` を置き換えない。**数学的に確定すること**と、**参考情報として採用してよいこと**は別である。

| 分類 | 必要条件 | 十分条件（本研究の範囲） | 未検証の条件 |
|---|---|---|---|
| **A. Determinate**（確定） | 有効な構成（GEOS `is_valid`）で、Feature内の構成どうしの重なりがない。地点が境界上でない | 同左（有効なPolygonでは規則によらず同じ） | GEOSの倍精度による境界の近くの誤差 |
| **B. Interpretation-consistent**（解釈が一致） | 地点が境界上でない（1mm以上）。面積0の環が地点の周りを回らない。Feature内の重なりに地点が入らない | 3系統5方式の関係が一致すること（本研究で確認）。H2 は、偶奇系と向き系の一致を保証し、GEOSの3方式とも観測上一致した | GEOSの修復方式の挙動の網羅、辺の交差・逆向き・はみ出した穴を含む実データ、**原典作成者の意図（C）** |
| **C. Interpretation-dependent**（解釈で異なる） | 5方式のどれかが異なる | — | どの解釈が意図に近いかは決められない |
| **D. Insufficient-evidence**（根拠不足） | 修復の失敗・面積なし、面積0の環が地点の周りを回る、Feature内の重なり、問題箇所の位置が特定できない、座標の精度が不明 | — | — |
| **E. On-boundary**（境界上） | 地点がリングから1mm以内 | — | 1mm の妥当性（座標の分解能・測位の誤差とは別） |

## 9. 内外判定の成立条件・判定保留の条件・未検証の条件

**成立する（本研究の範囲で根拠がある）**

- 有効な構成: 正式判定（GEOS）。地点の位置・Polygonの大きさによらない。
- 無効な構成で、地点が境界上でなく、H2 が成り立ち、面積0の環が地点の周りを回らず、Feature内の重なりに入らない: 偶奇系・向き系の規則は一致する（数学的）。GEOSの修復方式も一致した（観測）。→ **Bとしてのみ**成立する。

**判定を保留すべき**

- 地点が境界上（1mm以内）
- H2 が成り立たない（リングが2回巻く、逆向きの部分、はみ出した穴）: 解釈で異なる
- 面積0の環が地点の周りを回る
- Feature内の構成どうしが重なる位置
- 修復が失敗する、問題箇所の位置が特定できない

**まだ結論を出せない**

- 原典作成者の意図（C）との一致。頂点の接触が、作成時の細い水路・隙間を座標の丸めでつぶしたものか、意図した接触かは、データからは決められない。**問題箇所の近くでの保守的な判定保留（現行の `defect_within_*`）は、数学的には過剰でも、意図の不確かさに対する方針としては根拠がありうる**（検証していない）。
- 辺の交差・逆向きの部分を含む実データ（東京都の洪水には存在しない）。
- 浮動小数の座標（現行の索引）で、境界の近くの交差の数が正しく数えられる範囲。

| 1 | サイズに依存しない基本方式 | 地点を通る1本の半直線での、**リングごとの回転数**（と、そこから決まる偶奇・正規化した回転数）。有効な構成は従来どおり GEOS。計算量は半直線と交わる線分の数に比例し、面積・地点から境界までの距離に依存しない |
| 2 | 100m探索の位置付け | 判定の成立条件ではなく、(a) 境界の近く・最寄りの境界が複数の場合の検出、(b) 局所の読みと全体の読みの照合（逆向きの部分の検出に役立った: C10・C12）、(c) 問題箇所の近さ（意図の不確かさの目安。未検証）。**半径を広げても判定の根拠は増えず、現行条件では採用できる組が減る**（487 → 128 → 44） |
| 3 | 遠方の不整合を無視できる条件 | **距離では決まらない。** 地点のリングごとの回転数が H2 を満たし、面積0の環が地点の周りを回らず、Feature内の重なりに入らないとき、規則の上では不整合は地点の関係に影響しない（偶奇系・向き系は数学的、GEOSの方式は観測）。作成者の意図の上で無視できるかは分からない |

## 11. 共通Engineへの推奨事項と、追加で必要な検証

**次工程で採用できる（事実として記録するだけ。判定・採用条件は変えない）**

1. 共通契約 v0.2 の `analysis_state.far_reading` に、**リングごとの回転数（`raw_winding_per_ring`）・面積の符号・H2 の成否・境界までの全体の距離**を加える。既存のSQLite診断索引から、形式を変えずに求められる見込み（`DiagIndex.winding` の正規化前の値）。
2. 面積0の環の扱いを「その環が地点の周りを回るか」で記録する（判定には使わない）。
3. 研究用の分類（A〜E）は、内部の検証・データ品質の記録の軸として使い、`candidate / undetermined / rejected` とは別に持つ。

**追加の検証が必要（採用の前に）**

1. **Codexによる独立の監査**: 本研究のコード（`hererisk.research.point_study`）、H2 の数学的な整理（第3章）、反例探索の方法。
2. **精度**: 浮動小数での交差の数え方（頂点を通る半直線・ほぼ平行な辺）の頑健さ。整数の厳密な判定器（Phase 2-C.6 の方式E）との照合。1mm の境界の閾値の根拠。
3. **型の違う不整合を含む実データ**: 辺の交差・逆向きの部分を含むデータ（東京都の洪水にはない）。他の都道府県のA31a、A40・A49。
4. **地点の抽出**: 区分ごとの抽出ではなく、構成の面積に比例した無作為抽出・利用者の位置の分布に近い抽出での再検証。
5. **原典の意図（C）**: 公式の浸水想定区域図（PDF・GML）・作成者への確認と、無効な構成の一部を照合する方法の検討。照合がない限り、Cについて確認済みと主張しない。
6. **採用方針の判断**（OWNER）: H2 を参考解釈の条件に加えるか、`no_local_boundary` を H2 による全体の読みで置き換えるか、問題箇所の近くの保留を意図の不確かさとして残すか。いずれも版を上げた採用方針（`flood-diagnosis-adoption-v2` 等）として、回帰基準とともに検討する。
7. **性能**: H2 の計算をSQLite診断索引だけで行う実装の計測（常駐メモリなし）。`make_valid`・`buffer(0)` はリクエストの処理に使わない（最大36秒）。
