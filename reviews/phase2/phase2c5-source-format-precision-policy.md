## 2. GMLとGeoJSONの不一致の理由（N03 2026年版）

Phase 2-C.4では、N03 2026年版のGeoJSONを小数8桁に四捨五入すると、5,419件のFeatureでGMLと一致しない頂点があった。本工程で、外周の全969,214値（経度・緯度）を分類した。

| 分類 | 件数 |
|---|---|
| 四捨五入（`ROUND_HALF_UP`）でGMLと一致 | 918,859 |
| 一致しない（**すべて、GeoJSONのトークンが小数9桁で末尾が5の中間値**） | 50,355（約5.2%） |
| うち、偶数丸め（`ROUND_HALF_EVEN`）なら一致 | 22,697 |
| うち、どちらの丸めでも一致しない（GMLは切り下げ） | 27,658 |

- 中間値でない値は、すべて四捨五入で一致した。中間値に対するGMLの値は、切り上げ48,363・偶数丸め相当22,697・切り下げ27,658で、一定の十進の規則に従わない。
- 推定［未確認］: GMLの作成側が、十進の値を2進の浮動小数で表したうえで丸めたため、中間値の丸めの方向が値ごとに変わった。
- **結論**: GMLの8桁も、十進の規則による丸めの「正解」ではない。方針案は、決定的な十進の規則（`ROUND_HALF_UP`）を採用し、その結果を公式GMLの値と同一とは扱わない（方針案 第4.2節）。差は中間値で5×10⁻⁹度である。
- A40・A49のGeoJSONは13〜15桁で、ちょうどの中間値がなく、四捨五入でGMLと全件一致した（Phase 2-C.4）。

## 3. 合成データによる局所評価（丸めの影響）

標準ライブラリだけで、人工の座標を使って評価した。原典の精度の座標を10⁻¹⁵度単位の整数に、丸め後の座標を10⁻⁹度単位の整数にした。そのうえで、方針案のRC-1〜RC-7に相当する検査を行った。

| ケース | 結果 | 判定 |
|---|---|---|
| 01 小数15桁の座標（FP-1） | 5頂点が変化、最大変位1.23×10⁻⁹度、妥当性の変化なし | 受付 |
| 02 中間値で変わる頂点（FP-2） | 5頂点が変化、最大変位5×10⁻⁹度、妥当性の変化なし | 受付 |
| 03 隣接頂点が同一座標に潰れる（FP-3） | 丸め後に連続する同一頂点と自己接触が発生 | **停止** |
| 04 細いPolygonが消失する（FP-4） | 丸め後に面積0・縮退・向きの変化 | **停止** |
| 05 穴が外周に接するようになる（FP-5） | 丸め後に環どうしの接触が発生 | **停止** |
| 06 負の値の中間値（FP-11） | 絶対値で対称に丸めた（−0.000000005 → −0.00000001）。妥当性の変化なし | 受付 |
| 10 出典の異なる区域が丸めで同一になる（FP-10） | 丸め前は異なり、丸め後は同一 | 統合しない規則を確認 |

合成データでの結果は、実データでの成立の確認ではない（実データの丸めの影響は、方針案 第9章のPoCで確認する）。

## 4. 主な設計判断（未承認）

1. **形式**: GeoJSONを第一候補とするが、判定の基準FC-1〜FC-8で入力ごとに確認する。A40・A49・A33・N03 2026はGeoJSONを候補とし、A31aは現行のまま。
2. **座標参照系**: GeoJSONをRFC 7946準拠と推定しない。データソースごとの設定でJGD2011（EPSG:6668）・経度緯度を明示し、ファイルの `crs` メンバーと照合する。
3. **丸め**: 浮動小数を経由しない `Decimal` で、小数8桁・`ROUND_HALF_UP`（中間値は0から遠い方向。負の値は対称）に丸める。入力の桁数の上限は17桁とする。
   - 検索用の正規化座標だけを丸め、原典ZIPは変えない。頂点の追加・削除はしない。
   - 原典のトークン列のSHA-256で追跡し、Source Fidelity Validateで規則を再適用して照合する。
4. **停止の規則**: 丸めで構造・妥当性・向きが変わる場合（RC-1〜RC-7）は、取込みをBLOCKEDとする。不成立のFeatureだけを除外して成功にはしない。
5. **GMLの参照不整合**: 自動補正しない。検証結果として記録する。GeoJSONが独立に検証できればGeoJSONを候補とし、その検証が失敗すればFAILED/BLOCKEDとする。
6. **Floodとの関係**: 精度プロファイルを導入し、A31aは `coord-exact-9dp-v1`（現行）のままとする。N03の版の変更は、Integration契約のN03の入力資格と、新しいManifestで扱う。
