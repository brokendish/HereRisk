## 3. 合成ケースの一覧・結果

### 3.1 比較した判定器

| 記号 | 判定器 | 内容 |
|---|---|---|
| A | **参照判定器（本PoCで独立に作成）** | Pythonの整数だけで計算（浮動小数を使わない）。下記3.2の方式 |
| B | Shapely 2.2.0 / GEOS 3.14.1 | 面積交差は `relate` のDE-9IMの内部×内部（1文字目が `F` 以外）。接触は `intersects`。比較のため「交差面積 > 0」による判定も記録 |
| B' | 同上、度単位の浮動小数入力 | 座標を整数nano-degreeではなく、度の浮動小数で渡したもの（入力変換の影響を分離するため） |
| C | 既存の調査用判定器（Phase 2-A.4） | 問題の再現を目的とする参考値。正解の基準としない |

すべての方式に、同じ整数nano-degree座標を入力した（B'を除く）。Shapelyへは整数をfloat64に変換して渡した（地理座標の範囲では2^53未満で、変換は厳密）。

### 3.2 参照判定器の方式と、正しさの根拠の範囲

- **妥当性**: リングが閉じている、異なる点が3つ以上、面積が0でない、リングの自己交差・自己接触がない、リングどうしは孤立した点でしか接しない、穴は外周の内側（接点で分割した全区間で確認）、穴どうしの内部が重ならない、内部が連結（リングと接点の二部グラフに閉路がない）。OGCのSimple Featuresの規則に合わせた。
- **面積交差（2つの有効なPolygon）**: 境界が真に交差すれば面積交差あり。そうでなければ、各辺を相手の境界との全接点で分割し、各区間の中点（座標を2倍した整数で厳密に評価）が相手の内部にあれば面積交差あり。区間が相手の境界上にあれば、両方の内部が同じ側にあるかをリングの向きで判定する。接点のない区間の位置は直前の区間と同じなので、点の内外判定は接点ごとに1回で足りる。
- **点の内外**: 偶奇規則。境界上は「on」として返す。
- **根拠の範囲**: 上記の方式には、有効なPolygonについての正しさの論証（モジュールの説明に記載）がある。ただしそれは**形式的な証明ではなく、独立したレビューを受けていない**。合成ケースとファズ試験に合格したことは、一般的な正しさの証明ではない。

### 3.3 参照判定器の自己検証（ファズ試験）［実測］

小さな整数格子（6×6、10×10、40×40）上でランダムな多角形（長方形、星形、頂点の追加、穴、同一形状）を5万組生成し、参照判定器とShapely（小さな整数では述語が厳密）を比べた。

| 項目 | 結果 |
|---|---|
| 妥当性の判定 | 10万ポリゴンで差0（修正後。下記） |
| 面積交差／接触／交差なし | 両方とも有効な40,664組で差0（面積交差22,452、接触4,257、交差なし13,955） |
| 点の内外（半整数の点を含む） | 121,992点で差0 |

**ファズ試験で見つけて修正した参照判定器の欠陥**（2件）: (1) 穴が外周の頂点を通って外へ出る場合に有効と誤判定していた（穴の内側の確認を1点だけで行っていた）。全区間の確認に変更した。(2) 内部の連結性を検査していなかった。二部グラフの閉路検査を追加した。**参照判定器自体も誤りうることを示しており、製品化する場合は独立したレビューが必要である。**

### 3.5 合成ケースの集計［合成］

| 判定器 | 期待どおり（37ケース） | 主な不一致 |
|---|---|---|
| A 参照 | 37 | なし |
| B Shapely `relate`（nano整数入力） | 37 | なし（無効形状は `is_valid` で先に判定した場合） |
| B 「交差面積 > 0」 | 29 | 微小な交差（S14d・S15b）を「なし」、無効形状で例外・誤分類 |
| B' Shapely（度の浮動小数入力） | 35 | S15b・S15c（格子1つ分の差が度の浮動小数で表せない） |
| C 既存判定器 | 25 | **F-01の再現**（S01・S03b・S06a・S07a・S10a）、**区市町村単位の上書きの再現**（S17）、無効形状を検出しない（S16） |

**所見**:

1. **Codex指摘F-01は合成ケースで再現した。** 既存判定器は、完全一致・辺を共有する包含・頂点分割の違う一致・奇数長の辺の一致・穴ありの一致を「接触のみ」と誤分類した。Phase 2-B.2の対応表で静的に指摘した**区市町村単位の上書き**（同じ区市町村の別のポリゴンの「接触」で「面積交差」が上書きされる）も再現した（S17）。
2. **面積交差の判定に「交差面積 > 0」を使ってはならない。** GEOSの交差形状の計算は有限精度で、面積が極小の交差を失う。述語（`relate`）は同じ入力で正しかった。
3. **入力は整数nano-degreeのまま（float64へ厳密変換して）渡すべきである。** 度の浮動小数では、格子1つ分（10⁻⁹度の格子で、斜辺からの距離が約8×10⁻¹⁷度）の関係が表せない（S15b・S15c、P09・P10）。これは計算途中の誤差ではなく、**入力変換の誤差**である。
4. 合成ケースに合格したことは、各判定器の一般的な正しさの証明ではない。

**推奨構成（提案・未承認）**:

1. 製品の選別は、**STRtreeで候補を抽出し、GEOSの `relate`（DE-9IMの内部×内部）で判定する**。入力は整数nano-degreeをfloat64へ厳密に変換したもの。度の浮動小数・交差面積は使わない。
2. Integrated Validate（IV-4）の独立検証として、**整数の参照判定器で全件を再計算し、Bと全件一致を要求する**。1件でも不一致ならFAILED。GEOSの結果だけで候補を除外しない（契約 第6.5節）。
3. 判定の前に妥当性を検査し、**無効なポリゴンは判定保留**とする（扱いはOWNER判断。第10章）。
4. 既存の調査用判定器は使わない（F-01・上書きを合成ケースで再現し、巨大ポリゴンで5分を超える）。

## 9. Phase 2-A.4への影響

- **再評価した範囲［実測］**: 26成果品のうち4成果品（荒川・多摩川・入間川・神田川）の全件388,720ポリゴン。製品用ではない2つの判定器（独立に作った参照判定器と、Shapely / GEOS）で再計算した。「面積交差あり」のポリゴン数、区市町村の一覧、区市町村別の件数が、Phase 2-A.4の値と完全に一致した。標本1,266ポリゴンでは、ポリゴン単位の分類もPhase 2-A.4と一致した。
- **再評価していない範囲［未確認］**: 残り22成果品（東京都管理河川14、関東地方整備局の江戸川・中川・綾瀬川・浅川・大栗川・利根川・利根運河・坂川）。点の格子標本による重複統計（Phase 2-A.4 第5章）。
